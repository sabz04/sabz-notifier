# sabz-notifier

Уведомления о новых сообщениях **Avito** и **VK** в Telegram — чтобы ничего не потерять.

Шлёт только то, что написал **живой человек**: поддержка Авито, промо, доставка,
сообщества ВК, системные события чата («посмотрел номер», «создал чат») и твои
собственные исходящие — отсекаются. Первый опрос запоминает текущее состояние
молча, так что старые непрочитанные не прилетят пачкой.

## Установка на VPS одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/sabz04/sabz-notifier/vps/install.sh | sudo bash
```

Клонировать ничего не надо — скрипт сам скачает всё, что ему нужно. Он спросит
три вещи:

1. **Токен бота** — берётся у [@BotFather](https://t.me/BotFather)
2. **Кто управляет ботом** — `@username` или числовой id; команды от остальных
   молча игнорируются
3. **Кому слать уведомления** — `@username`, `@канал` или id. Можно с `@`, можно
   без. Enter — себе же

Дальше он сам поставит зависимости, при нехватке памяти добавит swap, заведёт
пользователя и службу systemd, проверит себя и запустится.

Всё сразу, без вопросов:

```bash
curl -fsSL https://raw.githubusercontent.com/sabz04/sabz-notifier/vps/install.sh | sudo bash -s -- --token 123456:AA... --owner sabzrr --recipient @sabzrr -y
```

Если репозиторий склонирован локально — то же самое через `sudo ./install.sh`.

**Повторный запуск = обновление.** Скрипт сам остановит работающий экземпляр,
положит свежий код поверх и запустит заново. Настройки и данные (куки, профиль
браузера, история) при этом сохраняются, токен подхватывается из прошлой
установки. Нужна переустановка совсем с нуля, вместе с данными — добавь
`--fresh`.

> **Владелец — это твой аккаунт в Telegram, а не имя бота.** Если вписать сюда
> `@имя_бота`, бот перестанет слушаться. Установщик такую ошибку теперь ловит
> сразу, а сам бот в ответ на команду от «чужого» объяснит, что поправить.

**Последний шаг:** получатель должен сам написать боту `/start`. Telegram не
разрешает ботам писать первыми — без этого уведомления не дойдут.

### Что делает install.sh

- ставит системные пакеты, при нехватке памяти создаёт swap 2 ГБ и прописывает его в fstab;
- заводит служебного пользователя `sabz` и каталог `/opt/sabz-notifier`;
- пишет `.env` с правами `640 root:sabz` — токен не виден посторонним;
- ставит юнит systemd с лимитами памяти и CPU, автозапуском и перезапуском при падении;
- в режиме `browser` — поднимает отдельный venv (системный python не трогает),
  ставит Chromium **вместе с системными библиотеками** и проверяет, что браузер
  реально запускается, а не просто скачался;
- прогоняет самопроверку и стартует службу.

Запускать можно сколько угодно раз — скрипт идемпотентный и подхватывает уже
введённый токен из установленного `.env`.

## Два режима

| | `light` (по умолчанию) | `browser` |
|---|---|---|
| Память | ~25 МБ | ~700–1200 МБ |
| Нужен браузер | нет | да, Chromium |
| Как даёшь доступ | присылаешь боту cURL в Telegram | логинишься один раз в окне браузера |
| Когда протухнет | пришлёшь новый cURL (бот сам попросит) | обычно не протухает |
| Требования | любой VPS | от 2 ГБ RAM |

### Что вообще нужно «достать»

Бот читает твои личные переписки, поэтому ему нужно доказать сайту, что это
ты. Способа два, и они принципиально разные:

- **`browser`** — доставать **не надо ничего**. Ты один раз логинишься в окне
  браузера бота, дальше он сам открывает мессенджер и читает список чатов.
  Куки живут и продлеваются сами.
- **`light`** — браузера нет, поэтому «доказательство» ты приносишь руками:
  для Авито это cURL (запрос со всеми твоими куками), для ВК — токен.

Если не хочется возиться — выбирай `browser`, там ручной работы ровно ноль
после первого входа.

### light: как дать доступ к Авито

Нужен **cURL запроса самой страницы мессенджера**. Список чатов Авито отдаёт
прямо внутри HTML — отдельного запроса за ним не существует, поэтому копировать
надо именно документ, а не первый попавшийся запрос.

1. Открой `avito.ru/profile/messenger` в браузере, где ты залогинен
2. Нажми **F12** — откроется панель разработчика
3. Вкладка **Network** (Сеть)
4. В строке фильтров нажми **Doc**
5. Обнови страницу — **F5**
6. В списке появится строка `messenger` — **правой кнопкой** по ней
7. **Copy → Copy as cURL (bash)**
8. Боту: команда `/avito`, следующим сообщением — вставить скопированное

Бот сразу проверит доступ и ответит, сколько чатов видит.

### light: как дать доступ к ВК

Проще токеном — одна ссылка и одно копирование.

1. Открой в браузере, где залогинен во ВК:

```
https://oauth.vk.com/authorize?client_id=2685278&scope=messages,offline&redirect_uri=https://oauth.vk.com/blank.html&display=page&response_type=token&revoke=1
```

2. Нажми **Разрешить**
3. Откроется пустая страница — смотри в **адресную строку**
4. Скопируй то, что после `access_token=` и до первого `&` (начинается на `vk1.`)
5. Боту: команда `/vk`, следующим сообщением — токен

Способ неофициальный: ВК не выдаёт право на чтение сообщений обычным
приложениям, поэтому используется идентификатор стороннего клиента. Аккаунт и
сообщения твои, но знать об этом стоит.

### Важное ограничение light-режима с Авито

Куки привязаны не только к аккаунту, но и к адресу. Если сервер не в РФ, Авито
на его IP покажет проверку «подтвердите, что вы не робот» — и твои домашние
куки этого не изменят. Пройти проверку можно только **с того же IP, откуда
ходит бот**, то есть в режиме `browser` через `sabz-notifier login`, либо
направив запросы Авито через российский прокси (`/proxy avito http://...`).

ВК таких проверок не устраивает и работает с любого адреса.

### browser — как войти

```bash
sudo sabz-notifier login
```

Поднимет браузер на сервере и покажет команду SSH-туннеля. Открываешь
`http://localhost:6080/vnc.html` у себя, логинишься в Авито и ВК — и всё.
Наружу порт не торчит, только через твой туннель.

## Управление

```bash
sabz-notifier status      # состояние + самопроверка
sabz-notifier logs -f     # логи вживую
sabz-notifier restart
```

## Удалить

Убрать бота, но сохранить данные (куки, историю, профиль браузера):

```bash
sudo sabz-notifier uninstall
```

Снести подчистую — данные, профиль, скачанный браузер, служебного пользователя
и swap, который создавал установщик:

```bash
sudo sabz-notifier uninstall --full
```

То же самое из папки репозитория: `sudo ./install.sh --uninstall` и
`sudo ./install.sh --purge`.

Системные пакеты (`python3`, `xvfb`, `novnc` и прочие) не трогаются даже при
полном удалении — их могли ставить не мы, и от них могут зависеть другие
сервисы на машине. Если уверен, что они больше не нужны, снимай их вручную.

## Изменить настройки

Посмотреть текущие (токен скрыт):

```bash
sabz-notifier config
```

Поменять один параметр — бот перезапустится сам:

```bash
sudo sabz-notifier config recipient @sabzrr
```

Ключи: `token`, `owner`, `recipient`, `mode`. Значение получателя можно писать
с `@` и без — приведётся само.

Переспросить всё заново (Enter — оставить как есть), с перезапуском и
самопроверкой в конце:

```bash
sudo sabz-notifier reconfigure
```

Часть настроек меняется **прямо из Telegram**, без захода на сервер:

```
/settings         все настройки и что из них можно менять
/recipient @name  кому слать уведомления (/recipient - — снова себе)
/interval 40      как часто проверять
/ignore слово     что не присылать
/mute /unmute     тишина
/restart          перезапустить бота
```

Смена режима с `light` на `browser` требует браузера, поэтому делается
переустановкой: `sudo ./install.sh --mode browser`.

## Команды бота в Telegram

```
/status          что настроено и живо ли
/settings        все настройки и как их менять
/recipient @name кому слать уведомления; /recipient - — снова себе
/interval 25     период опроса, секунды
/ignore слово    не слать, если слово есть в имени или тексте
/ignore          показать список; /ignore- слово — убрать
/mute /unmute    тишина
/restart         перезапустить бота
/test            проверить связь
/login           (browser) открыть Авито и ВК для входа
/proxy avito ... (light) HTTP-прокси для Авито
```

Управлять ботом может только владелец из `TG_OWNER` — остальные молча игнорируются.

## Что важно знать

**Авито проверяет незнакомые IP.** С VPS (особенно вне РФ) Авито отдаёт
`HTTP 429 «Доступ ограничен: проблема с IP»` — это не глухой бан, а проверка
«подтвердите, что вы не робот» с кнопкой. Её проходит человек, бот этого не
делает и не должен.

Главное: **проверку нужно пройти с того же IP, с которого ходит бот.** Сделать
это в домашнем браузере бесполезно — клирэнс привязан к адресу. На сервере это
значит режим `browser` и:

```bash
sudo sabz-notifier login
```

Открываешь через SSH-туннель, жмёшь кнопку — клирэнс ложится в куки профиля
бота, и он работает дальше сам.

Бот распознаёт эту страницу и **сразу пишет тебе в Telegram**, что нужно зайти
и пройти проверку, а когда она пройдена — сообщает, что продолжил. Повторные
напоминания приходят не чаще раза в час, проверяет он каждые 5 минут.

Альтернатива — выпускать запросы Авито через российский HTTP-прокси:

```
/proxy avito http://user:pass@host:port
```

ВК с зарубежных адресов работает нормально и проверок не требует.

**Один токен — один бот.** Telegram отдаёт `409`, если два экземпляра тянут
обновления одним токеном. Прежде чем запускать на сервере, останови бота на
другой машине.

**Разбор опирается на вёрстку Авито и ВК.** Если они переверстают страницы,
бот не упадёт — просто притихнет и напишет о проблеме, а селекторы надо будет
поправить.

## Windows (десктоп)

Тот же `bot.py`, запуск через `run.pyw` без окна консоли, настройки в `.env`
рядом (см. `.env.example`), автозапуск — задача Планировщика. Для браузерного
режима используется системный Chrome с отдельным профилем в `data/browser`,
основной профиль не трогается.

## Файлы

```
bot.py           весь бот (stdlib; playwright только для режима browser)
install.sh       установка и удаление на VPS
sabzctl          команда sabz-notifier
run.pyw          запуск на Windows без консоли
.env.example     образец настроек
```

Состояние и куки живут в `data/` и в git не попадают.
